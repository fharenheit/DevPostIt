# DevPostIt 코드 정리와 트레이 메모 설계

상태: 2026-11-01 사용자 ‘진행해’로 승인. 별도 구현자 관점 검토에서 중요한 미결 사항 없음.

## 요구의 출처

사용자는 코드 블록의 JSON·YAML·Java 등 언어별 정리, 메모 이름 변경, 실행 중 트레이 아이콘, 아이콘 클릭 시 새 메모, 우클릭의 설정·메모 목록을 요청했습니다. 제목 더블클릭은 **바탕화면에 작은 포스트잇 아이콘을 남기고 편집 창을 숨기며, 그 아이콘을 클릭하면 같은 메모를 복원**하는 방식으로 선택했습니다.

이는 사용자에게서 확인한 동작입니다. 원본 실행 파일을 분석해 확인한 사실로 취급하지 않습니다. 기존 승인 설계의 WPF·WebView2·Monaco·Markdown 정본과 작업 6의 자동 저장·복구를 이어 사용합니다.

## 구현 방식과 선택

- 창을 숨기고 작은 별도 창을 남기는 방식을 사용합니다. 사용자가 선택했습니다. 같은 편집 세션을 유지하므로 복원 시 커서와 저장되지 않은 편집을 보존할 수 있습니다.
- 창을 폐기한 뒤 다시 만드는 방식은 복원 때 편집기를 다시 초기화해야 합니다. 트레이에만 숨기는 방식은 사용자가 요청한 바탕화면 아이콘을 남기지 못합니다.
- 작성자 제안: 언어별 코드 정리는 편집기에 함께 배포한 포맷터로 수행합니다. JSON·YAML·JavaScript·TypeScript·HTML·CSS는 Prettier, Java는 Java 플러그인을 사용합니다. 외부 실행 프로그램을 매번 호출하는 방식보다 배포·응답 동작이 단순합니다. Java 브라우저 구동과 로컬 리소스 구성을 제작 빌드에서 검증합니다.

브라우저에서는 필요한 파서를 명시적으로 전달해야 합니다([Prettier 공식 문서](https://prettier.io/docs/browser)). Java 플러그인은 WebAssembly 문법 파일을 로드합니다([플러그인 구현](https://github.com/jhipster/prettier-java/blob/main/src/parser.ts)). 이 파일도 앱에 번들링하며, 필요한 경우 콘텐츠 보안 정책에 WebAssembly 컴파일 허용만 추가합니다. 임의 JavaScript 평가나 외부 리소스 허용으로 넓히지 않습니다. 구체적인 버전과 번들 구성은 구현·제작 빌드 검증에서 확정합니다.

## 코드 블록 정리

도구막대에 ‘코드 언어’ 선택과 ‘코드 정리’ 버튼을 둡니다. 기본 선택은 블록에 적힌 언어를 따릅니다. 언어 표시가 없는 블록은 사용자가 언어를 선택할 수 있습니다. 지원 언어는 JSON, YAML, Java, JavaScript, TypeScript, HTML, CSS입니다. `jsonc`, `yml`, `js`, `ts` 같은 일반 별칭도 처리합니다.

버튼과 단축키는 커서가 있는 최상위 fenced code block의 코드 부분만 바꿉니다. 앞뒤 Markdown과 울타리·언어 표시는 유지합니다. 정리 결과는 한 번의 실행 취소로 되돌릴 수 있고 일반 편집처럼 자동 저장됩니다. 닫히지 않은 블록, 미지원 언어, 문법 오류는 본문을 바꾸지 않고 이유를 표시합니다. 처음에는 목록·인용 안의 중첩 코드 블록을 정리하지 않으며 이를 안내합니다.

정리 중 사용자가 다른 메모를 열거나 본문을 바꾸면 이전 계산 결과를 적용하지 않습니다. 미리보기 상태와 한글 조합 중에는 코드 정리를 실행하지 않습니다. 자동 저장할 때마다 강제로 정리하지 않습니다.

## 메모 이름

제목 옆 ‘이름 변경’ 버튼으로 편집하고 확인·취소할 수 있습니다. 제목 자체의 더블클릭은 접기 동작입니다. 공백만 있는 이름은 거부하고 앞뒤 공백을 제거합니다. 작성자 제안으로 최대 길이는 200자입니다.

이름은 Markdown 앞부분의 `title`에 저장하고 검색 인덱스에도 반영합니다. 파일 경로와 메모 ID는 그대로 유지합니다. 제목 변경과 본문 편집은 같은 리비전·복구 저널·자동 저장 흐름을 사용하여 서로 덮어쓰지 않습니다. 재실행한 창과 트레이 목록에도 저장된 제목을 표시합니다.

## 트레이와 다중 메모

앱이 시작하면 트레이 아이콘을 등록하고 기존 메모 하나를 엽니다. 데이터가 없으면 첫 메모를 생성합니다. 트레이 아이콘을 왼쪽 클릭하면 고유 ID를 가진 새 메모를 만들어 엽니다.

우클릭 메뉴는 ‘새 메모’, ‘메모 목록’, ‘설정’, ‘모두 표시’, ‘모두 접기’, ‘종료’를 제공합니다. 메모 목록은 저장된 모든 메모의 현재 제목을 보여 주며, 선택하면 이미 열린 창을 복원하거나 해당 메모를 엽니다. 같은 메모의 편집 창을 중복 생성하지 않습니다.

제목을 더블클릭하면 편집 창을 숨기고 그 위치 가까이에 작은 포스트잇 창을 표시합니다. 작은 창은 드래그할 수 있고, 한 번 클릭하면 편집 창을 복원합니다. 화면 작업 영역 안에 놓습니다. 작은 아이콘에는 메모 제목을 도구 설명으로 제공합니다.

창의 닫기 버튼은 현재 메모 창을 저장하고 닫습니다. 메모 파일은 유지하며 트레이 목록에서 다시 열 수 있습니다. 편집 창을 모두 닫아도 트레이는 계속 실행됩니다. 앱 전체 종료는 트레이의 ‘종료’를 사용합니다. 현재 창들에 전달 전인 초안이 있으면 먼저 수집하고, 작업 6의 저장 실패·미보존 초안 방지 규칙을 유지합니다. 정상 종료 시 트레이 아이콘과 창·편집기를 정리합니다.

여러 창은 앱이 소유한 저장소·자동 저장 서비스·데이터 폴더 임대를 공유합니다. 임대를 개별 메모 창이 해제하지 않습니다. 다른 프로세스의 동시 저장은 기존 배타적 임대가 거부합니다.

## 설정

트레이의 ‘설정’은 열린 편집기의 설정 대화상자를 엽니다. 열린 창이 없다면 기존 메모 하나를 열어 표시합니다. 글꼴, 합자, 전체 글자 크기를 조절합니다. 기본 UI 15px·편집기 13px와 전체 크기 10~24px 제한을 유지합니다. 변경한 설정은 재실행 후에도 유지하고 열린 다른 메모 창에도 적용합니다.

## 구조와 단계

1. 웹의 코드 블록 탐색·언어별 정리와 Monaco 실행 취소 연동을 먼저 구현하고 검증합니다.
2. 제목을 브리지·서비스·메타데이터·인덱스까지 연결하고 재시작 보존을 검증합니다.
3. 저장소의 메모 열거와 앱 수명의 공유 저장 세션, 트레이·다중 창·작은 아이콘·설정을 연결합니다.

각 단계는 실패하는 테스트부터 시작하고 통과한 뒤 커밋합니다. 기존 파일 감시·충돌 해결 작업 7 전체와 중앙 관리 화면 전체는 이 추가 요청과 별도입니다.

## 완료 기준

- JSON·YAML·Java를 포함한 지원 언어의 실제 정리 결과를 제작 빌드에서 검증합니다. 오류·범위 밖 변경·실행 취소·비동기 경합도 검사합니다.
- 이름 변경 뒤 본문과 ID가 유지되고, 재시작·복구·검색·트레이 목록에 이름이 반영됩니다.
- 실제 WPF에서 트레이 새 메모, 독립된 두 메모의 저장, 제목 더블클릭 접기, 아이콘 클릭 복원, 우클릭 목록·설정·종료를 확인합니다.
- 마지막 창 닫기 이후에도 트레이가 남고, 전체 종료는 모든 메모의 저장을 확인합니다. 저장 실패 시 작업 6의 초안 보호가 작동합니다.
- .NET·웹 회귀 테스트와 제작 빌드가 통과하며 검증 기록을 남깁니다.
