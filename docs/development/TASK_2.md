# 작업 2 실행 기록

계획: `docs/superpowers/plans/2026-11-01-hunmin-notes.md` 작업 2.
기준 커밋: `389559b`. 작업 브랜치: `codex/task-2-markdown-storage`.

## 범위와 계약

- `FrontmatterCodec.Parse`는 기존 ID가 있는 문서를 읽으며 파일을 변경하지 않습니다.
- `FrontmatterCodec.Import`는 명시적 가져오기입니다. ID가 없을 때만 새 ID를 부여하며, 없는 제목은 파일명, 시각은 UTC 현재 시각, 태그는 빈 목록으로 정합니다. 기존 ID는 유지합니다.
- `MarkdownNoteRepository.ImportAsync(raw, relativePath, cancellationToken)`는 가져온 문서를 비어 있는 대상 경로에 저장합니다. 원본 파일은 별도로 읽어 전달하며, 기존 파일을 가져오기 대상으로 지정하면 거부합니다.
- 메모 루트는 생성자에 전달합니다. `notes/` 디렉터리를 지정하는 것이 의도된 사용입니다. 경로는 루트 기준이며 반환 경로의 구분자는 `/`입니다.
- 인덱스 없이 `.md` 파일을 스캔합니다. ID가 없는 일반 Markdown은 건드리지 않고 건너뜁니다. 잘못된 메타데이터는 오류로 보고하며 자동 교정하지 않습니다.
- 중복 ID가 발견되면 조회·저장을 중단합니다. 기존 ID를 다른 경로로 저장하거나 다른 메모가 점유한 경로를 덮어쓰지 않습니다. 외부에서 이미 이동한 파일은 다음 조회 시 새 경로로 찾습니다.
- 절대 경로, 상위 경로, ADS, Windows 예약 이름, 끝의 점·공백, 비 Markdown 확장자를 거부합니다. 정션·심볼릭 링크 등 재분석 지점도 거부합니다.

## 판단 기록

- 판단: 전체 YAML을 직접 구현하지 않고 [YamlDotNet 공식 배포](https://www.nuget.org/packages/YamlDotNet/18.1.0)의 안정 버전 18.1.0을 고정했습니다. YAML 인용·유니코드 해석 오류를 줄이기 위한 선택이며 패키지 잠금 파일도 포함합니다.
- 판단: `Note` 계약에 담을 수 없는 알 수 없는 Frontmatter 키는 거부합니다. 이를 무시하면 저장 시 데이터가 유실됩니다. 향후 임의 메타데이터를 지원하려면 도메인 계약 확장이 필요하며, 그때까지 확장 필드 문서는 가져올 수 없습니다.
- 판단: 일반 읽기는 필수 필드와 시간대가 있는 ISO 시각을 요구합니다. 명시적 가져오기에서만 누락 필드를 기본값으로 채웁니다. 잘못된 기존 값은 가져오기에서도 거부합니다. 모호한 문서를 자동 보정하는 편의성은 제한됩니다.
- 판단: 작업 1과 동일하게 현재 체크아웃의 별도 브랜치에서 실행합니다. 기본 브랜치와 원격은 변경하지 않습니다.
- 사전 인터페이스 검토: 작업 1의 `INoteRepository`와 `Note`를 그대로 구현합니다. 작업 6의 원자적 저장과 작업 7의 외부 변경 조정은 이 저장 경로에 추가되어야 합니다. 현재 계약과 충돌은 없습니다.

## 검증

Windows에서 `.tools/dotnet/dotnet.exe`로 실행했습니다.

1. 시작 전 전체 테스트: 기존 3개 통과.
2. 테스트를 먼저 작성하고 미구현 계약으로 Storage 테스트 실행: 30개 전부 실패. 원인은 `NotImplementedException`으로 확인했습니다.
3. 구현 후 29개 통과, 1개 실패: ID가 이미 있는 문서를 점유된 일반 파일 경로로 저장할 때 경로 충돌 대신 ID 충돌을 먼저 반환했습니다. 대상 파일 점유 검사를 우선하도록 수정했습니다.
4. 전체 테스트 재실행: Core 3개, Storage 30개, 합계 33개 통과.
5. 계획의 Frontmatter 필터 테스트 14개 통과, 잠금 복원 성공, WPF 포함 빌드 경고·오류 0.
6. 별도 코드 검토에서 같은 ID·같은 경로의 가져오기가 기존 메모를 덮어쓸 수 있음을 발견했습니다. 재현 테스트를 먼저 추가해 예외가 발생하지 않는 실패를 확인한 후, 가져오기는 저장 잠금 내부에서 기존 대상 파일을 거부하도록 수정했습니다. 전체 34개 통과.
7. 최종 잠금 복원 성공, WPF 포함 빌드 경고·오류 0, 전체 테스트 34개 통과. 최초 코드 검토에서 추가 주요 문제는 발견되지 않았습니다.

테스트는 실제 일회용 파일을 사용합니다. 한글 제목·태그, YAML 인용·다중 행, 메타데이터 및 본문 왕복, CRLF와 빈 본문, 명시적 ID 부여, 잘못된 YAML/ID/필드 거부, 저장·재조회·갱신, ID 및 경로 충돌 시 기존 파일 보존, 경로 순회·정션 차단, 취소 시 미기록을 검증합니다.

## 남은 범위

저장소는 아직 앱에 연결하지 않았습니다. 원자적 저장·저널·디스크 오류 복구는 작업 6, 외부 수정 충돌 감지는 작업 7의 범위입니다. 현재 저장은 같은 인스턴스 내에서 직렬화하지만 다른 프로세스의 파일 변경과 검사 사이 경쟁까지 해결하지 않습니다. 원본 프로그램의 REA 실행 관찰은 일회용 VM이 없어 계속 보류합니다. 작업 3은 시작하지 않았습니다.
