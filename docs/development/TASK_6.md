# 작업 6 실행 기록

기준 커밋 `ca18575`, 브랜치 `codex/task-6-autosave-recovery`.
계획 `docs/superpowers/plans/2026-11-01-hunmin-notes.md` 작업 6을 실행합니다.

## 설계·경계

- `NoteService`는 Core의 저장소·복구 저널·인덱스 쓰기 인터페이스만 사용합니다. 메모별 잠금으로 리비전을 직렬화하고 500ms debounce를 적용합니다.
- 변경을 수락하기 전에 최신 초안을 원자적인 복구 저널에 기록합니다. 저장 순서는 저널 → Markdown 파일 → SQLite 인덱스 → 저널 정리입니다.
- 파일 저장 실패 시 이전 파일과 메모리·저널 초안을 유지합니다. 파일은 저장됐지만 인덱스가 실패한 경우 이를 별도 상태로 표시하고 재시도 시 파일을 다시 쓰지 않습니다.
- `AtomicFileWriter`는 동일 디렉터리 임시 파일에 UTF-8을 쓰고 Flush(true) 후 Windows File.Replace 또는 새 파일 Move로 교체합니다. 실패 시 비원자적인 덮어쓰기 대안으로 전환하지 않습니다.
- 재시작 시 저널의 초안과 원본 파일을 함께 유지하며 사용자가 복구 또는 원본 유지를 선택합니다. 이미 저장된 내용의 저널은 인덱스 갱신 후 정리합니다.
- 저장 직전 기본 파일 지문을 비교해 디스크 변경 시 덮어쓰기를 거부합니다. 감시·충돌 복사본 및 해결 UI는 작업 7입니다. 저장 직전 검사와 원자 교체 사이 외부 변경 경쟁은 아직 별도 파일 조정이 필요합니다.
- WPF는 문서/DevPostIt 폴더의 첫 메모를 열고 자동 저장을 연결합니다. 통합 검증은 `DEVPOSTIT_DATA_DIR`로 별도 일회용 데이터를 사용합니다. 기존 메모 관리자 UI는 추가하지 않습니다.
- 테스트는 FakeTimeProvider와 제어 가능한 저장소로 debounce·저장 순서를 검증하며 실제 파일 잠금·강제 종료 자식 프로세스도 사용합니다. 테스트 전용 동작은 테스트 프로젝트에 둡니다.
- 기존 사용자 변경 `editor-web/README.md`는 보존하고 커밋하지 않습니다.

## 실행 순서

- [x] 실패 테스트: debounce, 직렬 리비전, 저장 실패·인덱스 실패 재시도, 복구 승인, 원자적 파일 실패 보존.
- [x] 최소 구현 및 Core/Storage 테스트 통과.
- [x] 일회용 데이터에서 실제 자식 프로세스 강제 종료·복구 검증.
- [x] WPF와 연결해 자동 저장·Ctrl+S·재시작 문서 복원 확인.
- [x] 전체 테스트·빌드·별도 검토 후 작업 6 커밋. 작업 7은 시작하지 않습니다.

## 실행 증거

- 시작 전 전체 .NET 테스트 88개 통과.
- NoteService 테스트 8개, AtomicFileWriter 테스트 3개, FileRecoveryJournal 테스트 4개가 미구현 상태에서 실패했습니다. 파일 잠금 보존 테스트는 기존 구현에서도 통과했으므로, 기존 독자가 이전 파일을 계속 읽는 교체 테스트를 추가해 실패를 확인했습니다.
- FakeTimeProvider로 마지막 입력 이후 499ms에는 파일 저장이 없고 500ms에 최종 초안만 저장되는 것을 검증했습니다. 디스크 부족은 저장소 실패로 모사했으며 메모리·저널 보존 및 재시도를 확인했습니다.
- 실제 Windows 파일 잠금으로 교체 실패 시 이전 바이트와 임시 파일 정리를 확인했습니다. `FileStream.Flush(true)`와 `File.Replace`를 사용하며 비원자적 쓰기로 우회하지 않습니다.
- 실제 자식 프로세스에서 저널 기록 완료 후 강제 종료했습니다. 기존 Markdown은 유지됐고 재시작 서비스가 초안을 복구 후보로 읽었습니다. 복구 승인 후 파일 저장·저널 정리를 확인했습니다.
- 실제 WPF WebView2에서 Ctrl+S 없이 자동 저장, 파일의 한글 본문, 저장 응답, 미리보기를 확인했습니다. 창을 정상 종료·재시작한 뒤 본문 복원을 확인했습니다. `editor-web/scripts/wpf-autosave-smoke.mjs`로 재현합니다.
- 별도 검토에서 종료 스냅샷 실패 시 미전달 초안 유실, 중복 앱의 공유 저널 삭제 위험 2건을 발견했습니다. 각각 종료 스냅샷 검증과 데이터 폴더 배타 임대 테스트를 먼저 실패시킨 뒤 보완했습니다.
- WPF는 최신 화면 초안 수집·반영이 실패하면 서비스가 clean이어도 종료를 차단합니다. 실제 제한 초과 초안을 로드해 종료 요청 후 프로세스 유지·기존 파일 해시 보존을 확인했고, 네이티브 경고 문구도 읽었습니다. 거대한 한 줄 붙여넣기는 편집기 비용 때문에 중단하고 여러 줄의 제한 초과 문서를 공개 load 계약으로 로드해 종료 안전성만 분리 검증했습니다.
- `DataDirectoryLease`는 데이터 폴더의 OS 파일 핸들을 배타적으로 유지합니다. WPF와 크래시 하네스가 이를 보유하며, 두 번째 작성자를 거부하고 강제 종료 후 다시 획득되는 것을 검증합니다. 같은 파일 저널을 사용하는 다른 호출자도 동일한 임대를 보유해야 합니다.
- 최종 .NET 테스트 111개(Core 14, Storage 68, Bridge 29)와 개발 서버 웹 테스트 19개가 통과했습니다. 잠금 파일 복원과 WPF 포함 빌드도 성공했습니다. 기존 Monaco 청크 크기 경고는 남아 있습니다.
- 변경을 확정하지 못한 초안의 시험은 일회용 데이터에서만 실행했습니다. 실제 OS 전원 차단이나 저장 장치 자체의 장애까지 통과했다고 주장하지 않습니다.

## 남은 경계

외부 변경 시 자동 덮어쓰기는 거부하지만 감시·충돌 복사본·해결 UI는 작업 7입니다. 현재 WPF는 첫 메모 하나를 열며 목록·이름 편집·트레이는 아직 없습니다. 저장 성공 이후 인덱스 실패는 파일 저장 상태와 분리해 표시하고 저널을 유지합니다. 복구 저널은 장기 백업을 대신하지 않습니다.
