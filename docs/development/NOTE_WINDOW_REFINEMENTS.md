# 메모 창 간소화·삭제·최소화 검증

2026-11-01 사용자의 여섯 가지 후속 지시를 기존 설계보다 우선 적용했습니다.

## 동작

- 제품명·새 메모·이름 변경 버튼을 메모 화면에서 제거했습니다. 새 메모는 트레이에서 생성합니다.
- 본문 위 제목의 더블클릭은 이름 편집을 엽니다. Windows 제목 표시줄 더블클릭은 아래 ‘제목 표시줄·드래그·코드 하이라이트’에 따라 아이콘으로 접습니다. 웹·트레이·대화상자에는 제품명을 표시하지 않습니다. 창 제목은 아래 ‘창 제목·보기 전환 글꼴’을 따릅니다. 내부 실행 파일명과 데이터 경로는 유지합니다.
- 글꼴·합자·전체 글자 크기는 설정 대화상자에만 표시합니다. 트레이 설정 또는 Ctrl+,로 열고, 변경은 열린 다른 메모와 재실행에도 반영됩니다.
- 최소화는 24×24px 빈 노란 아이콘으로 접습니다. 기존 48px의 가로·세로를 절반으로 줄였습니다. 클릭 복원과 드래그 이동을 유지합니다.
- 메모 창의 X는 ‘메모를 영구 삭제하시겠습니까?’를 묻습니다. 기본 선택은 ‘아니요’이며, ‘예’는 대상 ID의 파일·저널·검색 항목을 제거합니다. 트레이 종료는 모든 메모를 보존하며 닫습니다.

## 저장과 취소 보호

삭제는 자동 저장과 같은 메모별 게이트를 사용하고 타이머를 중지합니다. 삭제된 세션의 후속 변경·저장은 거부하고, 늦은 상태 이벤트가 목록에 메모를 다시 추가하지 않도록 캐시 삭제를 잠금과 tombstone으로 보호합니다. 파일 삭제 실패 시 원래 복구 기록을 다시 보존하고 파생 검색 항목을 복구합니다.

사용자가 삭제 확인에 응답하는 동안 초기화와 메시지 처리를 중지하지 않습니다. 실제 삭제·닫기 중 도착한 메시지는 보류하고, 실패·취소 시 다시 처리합니다. 따라서 이미 전송한 최신 입력이 재전송되지 않아 사라지는 경로를 막습니다. 진행 중인 닫기를 트레이 종료가 기다릴 때 원래 닫기 방식도 바꾸지 않습니다.

Windows의 사용자 닫기 명령과 앱의 보존 닫기를 구분합니다. 최소화에서 경고를 표시할 때는 창을 먼저 보인 뒤 정상 상태로 복원하여 이후 최소화 이벤트도 계속 작동하게 합니다.

## 검증

- 웹 **37개**, 개발 서버와 제작 빌드 모두 통과: 화면 제어 제거, 제목 더블클릭, 설정 이동·영구 저장, 기존 포맷터·IME·원문 보존 포함.
- .NET **125개**: Core 18, Bridge 32, Storage 75.
- 삭제 API 부재와 화면 단순화 요구의 실패 테스트에서 시작했습니다. 대상만 삭제·다른 메모 보존, 실제 파일 잠금 시 실패·재시도, 마지막 메모 ID 재사용 방지 테스트를 추가했습니다.
- 새 메모는 복구 폴더가 없을 수 있습니다. 마지막 메모 삭제 테스트에서 이 경우의 `DirectoryNotFoundException`을 발견하고 저널 제거를 멱등적으로 처리했습니다.
- 별도 검토에서 찾은 삭제 실패 후 복구 기준 지문 변경을 실패 테스트로 재현했습니다. 기존 `RecoveryDraft` 전체를 복원해 외부 변경 충돌이 유지됨을 확인했습니다.
- WPF·WinForms 하네스로 초기화 중 삭제 취소, 삭제 실패 중 늦은 제목 메시지, 미보존 초안 종료 차단, 반복 최소화·24px 빈 아이콘·클릭 복원, X 확인의 아니요/예, 다른 메모 보존, 트레이 목록·설정·종료 경합을 확인했습니다. 메뉴·버튼 이벤트 검증과 셸의 물리 마우스 드래그는 구분합니다.
- 별도 실행 파일의 실제 WebView2에서 Java·JSON 코드 정리와 두 메모의 제목·본문 저장도 확인했습니다.
- 잠금 파일 복원과 WPF 빌드 성공. 기존 웹 번들 경고는 첫 구현 검증 문서와 같습니다.

검증 명령과 하네스 실행 방법은 [첫 구현 검증](FORMATTING_TRAY.md)의 재실행 절차를 사용합니다. 사용자 수정 editor-web/README.md는 보존했습니다.

## UI 배치 개선

2026-11-01 사용자 요청과 승인한 계획에 따라 메모 창 배치를 정리했습니다. 저장·브리지·삭제 동작은 바꾸지 않았습니다.

- 제목과 보기 전환을 헤더 한 줄에, 상태와 코드 도구를 하단 바 한 줄에 둡니다. 바깥 카드 여백, `MD` 배지, 고정 안내 문구는 제거했습니다. 좁은 창이나 큰 글자에서는 줄바꿈하며, 긴 상태 문구는 코드 도구를 밀어내지 않고 상태 영역 안에서 스크롤합니다.
- 색은 `style.css`의 `:root` 토큰으로 모으고 트레이 아이콘에 맞춰 노란 메모지 색을 씁니다. Monaco의 `devpostit-paper` 테마는 같은 값을 사용합니다.
- 설정은 항목별 행으로 정리했습니다. 미리보기에서는 코드 언어와 코드 정리를 비활성화합니다.
- 창은 기본 480×640, 최소 320×360입니다. 네이티브 제목 표시줄은 유지하고 DWM으로 색만 지정합니다. Windows 10에서는 기본 색으로 표시됩니다.
- 접힌 아이콘은 전용 버튼 템플릿으로 마우스를 올려도 노란색을 유지하고 테두리만 진해집니다.

### 검증

- 웹 **53개**, 개발 서버와 제작 빌드 모두 통과. `editor-web/tests/layout.spec.ts`에 16개를 추가했습니다(창 채움, 본문 비율, 304×320~1200×850과 글자 10·15·24px의 넘침, 긴 오류 표시, 미리보기 중 코드 도구, 대비 4.5:1, 설정 행, Monaco 배경).
- .NET **125개**(Core 18, Bridge 32, Storage 75) 통과. WPF 하네스에 창 크기와 접힌 아이콘 템플릿 검사를 추가했고 통과했습니다.
- 별도 데이터 폴더로 실행 파일을 띄워 메모 창과 제목 표시줄 색을 화면 캡처로 확인했습니다.
- 물리 마우스로 확인하지 않은 항목: 접힌 아이콘의 hover 색. Windows 10의 제목 표시줄과 고배율 DPI도 확인하지 않았습니다.

## 제목 표시줄·드래그·코드 하이라이트

2026-11-01 사용자 지시를 이전 문서보다 우선 적용했습니다.

- Windows 제목 표시줄 더블클릭은 이름 편집 대신 24px 아이콘으로 접습니다. 본문 위 제목의 더블클릭은 이름을 바꾸는 경로이므로 유지합니다. 쓰지 않게 된 `ui.openRename` 메시지는 제거했습니다.
- 접힌 아이콘은 드래그로 옮길 수 있습니다. 실제 마우스 입력으로 재현한 원인은 버튼의 마우스 캡처로, `DragMove` 전에 해제합니다. 이동 뒤 복원했다가 다시 접으면 아이콘은 메모 창 위치에서 다시 시작합니다.
- 코드 블록은 Monaco의 언어 정의와 `monaco.editor.colorize`로 소스 편집·미리보기 모두 색을 구분합니다. 새 npm 패키지 없이 오프라인으로 동작합니다. 언어 목록은 `editor-web/src/code-languages.ts`에 있고, JSON은 색 구분 전용 토크나이저를 씁니다. 언어를 모르거나 지정하지 않은 블록은 평문으로 둡니다. 미리보기 표시만 바꾸며 원문과 초안은 변경하지 않습니다.

### 검증

- 웹 **73개**, 개발 서버와 제작 빌드 모두 통과. `highlight.spec.ts`에 20개를 추가했습니다(언어 12종, 글자·들여쓰기 보존, 코드 안 HTML 미실행, 메모 전환 경합, 소스 편집 색, 대비 4.5:1).
- .NET **125개** 통과. WPF 하네스에 제목 표시줄 더블클릭 메시지와 아이콘의 실제 마우스 입력(`SetCursorPos`·`mouse_event`) 드래그·클릭 복원 검사를 추가했습니다. 하네스 실행 중 커서가 잠깐 움직이므로 그동안 마우스를 건드리지 않습니다.
- 별도 데이터 폴더의 실행 파일에서 제목 표시줄 실제 더블클릭, 아이콘 실제 드래그, 클릭 복원을 확인했습니다. 드래그 시작 임계값 때문에 아이콘은 커서 이동량보다 약 6px 덜 움직입니다.

## 창 제목·보기 전환 글꼴

2026-11-01 사용자 지시입니다. Windows 제목 표시줄은 메모 이름 대신 항상 ‘Post It for Developer’를 표시합니다. 작업 표시줄과 Alt+Tab에서도 같은 문구로 보입니다. 소스 편집·미리보기 버튼은 0.875rem(기본 13.125px)으로 줄였고 전체 글자 크기 설정을 계속 따릅니다.
